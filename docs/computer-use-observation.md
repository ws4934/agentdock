# Computer Use：单次输入后的观察

`desktop_act` 支持可选的 `observe_after: true`。它仍只执行一个动作；输入成功后，在同一任务、控制代次和串行锁内，对刚才的后台窗口获取一次新快照。客户端读取这次结果后再决定下一步，不提交动作数组，也不在工具内部循环点击。

```json
{
  "task_id": "<当前任务的私有令牌>",
  "action": "click",
  "snapshot_id": "<刚观察获得的单次ID>",
  "element_id": "<该快照中的控件ID>",
  "observe_after": true
}
```

仅适用于明确绑定的后台窗口；前台快照会在发送输入前拒绝该选项。省略该字段保持原有行为。启动应用后仍需先 `desktop_snapshot`，不能以启动返回值代替输入许可。

## 返回与验证

成功获取观察时，`observation_status: "captured"`，`observation` 是新的后台快照，包含窗口、AX 元数据、坐标映射和单次 `snapshot_id`。截图作为标准 MCP image content 返回，不把 Base64 混进文本或嵌套结构化结果。客户端必须先审阅图像/控件状态，才能使用新 ID 发送下一次动作。

观察继承原快照的 `screenshot`、`accessibility` 和大小/遍历限制；不会把 `screenshot:false` 偷偷升级为截图，也不会重新选择其他应用。快照缓存只保留必要状态，不保存图像字节或任务私有令牌。

`event_dispatched:true` 仍只表示输入已投递，`application_verified:false` 不变。即时快照可能早于应用异步更新；需要等待时使用只读 `desktop_wait` 或重新观察，而不是再次点击。AXValue、选中文本和密码字段的读取边界不变；计算器显示值可以通过窗口图像核验，不能因为看到历史记录便宣称已读到具体数字。

## 失败、停止与单步

输入失败或可能只执行一部分时，沿用原有错误，不自动执行动作后观察，也不重放输入。

输入成功但后续截图、权限检查或目标观察失败时，保留 `event_dispatched:true`，返回 `observation_status:"unavailable"` 和独立的 `observation_error`。其中 `input_already_dispatched:true`、`retry_input:false` 明确表示不能因为观察失败而重复点击；此时不给新快照令牌。

观察前后都检查同一控制代次；暂停、停止、断联和清理失败不会触发重新获取许可或其他输入路径。本机“下一步”仍最多允许一个动作，观察证据可返回，但 `snapshot_id` 为空、有效期为 0、`observation_only:true`；本机恢复后必须重新观察。

## 界面

控制窗保留应用、任务、状态、预览和操作按钮，删除常驻预览说明、重复提示及静止画面告警。应用授权仍展示身份，前台模式仍提示桌面影响，停止未确认和手动清理提示保留。

权限页保留菜单应用与 Core 的独立状态、请求/设置入口、自动刷新和恢复入口；解释性段落改为按需查看，路径与详细说明放入提示或恢复对话框。

## 验证范围

`observation_test.go` 使用内存后端验证单次投递、新旧快照、截图设置继承、失败不重试、目标身份变化、停止和单步限制；Runtime 契约与 MCP 测试验证参数及图像传输。UI 文案回归检查配合 Swift 编译，不等同于真实窗口视觉验收。

这项改动减少工具往返，不承诺绕过客户端安全判定，也不提供无人值守批量队列。升级 Core 和菜单应用、刷新 MCP 工具定义后，才能在连接中使用新字段。
