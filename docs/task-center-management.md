# 任务中心管理与菜单唤起（0.8.8）

## 菜单修复

任务中心和连接诊断的菜单 target/action 原本有效，但窗口展示没有激活 accessory 应用。三个管理窗口统一使用 `ManagementWindowPresenter`：恢复最小化窗口、重新定位已离开现有屏幕的窗口、展示并激活应用，再将窗口置前。展示窗口不依赖 Core 健康，不启动或重启服务。

## 操作范围

列表支持 Command/Shift 多选。归档仅设置 `archived_at`，不改变原始状态、步骤、事件或最终验收；精确编号仍可读取，已有任务仍能更新进度。在“已归档”中恢复后重新出现在普通列表。归档不停止命令。

永久删除仅允许已完成任务。“清理当前已完成”只选择当前筛选结果中已经显示的已完成记录，不扩大到搜索隐藏或更早的任务。部分列表继续明确提示。删除确认的默认回车操作是取消。未完成任务只能归档，不能强制删除。

清理只删除任务 JSON 记录，保留执行回执、日志、防重放墓碑、冻结交付和已交付文件，因此不是清除全部执行缓存的入口。删除不可撤销，归档可恢复。

## 并发与故障

确认框冻结明确的 ID 和 `tsk1:` 版本指纹。记录在后台变化后，旧请求报告 TASK_CONFLICT，不覆盖新进度。原生管理 POST 只接受 archive/restore/delete 和 1–200 个唯一编号及指纹；整份请求先验证再写入，拒绝未知字段、尾随 JSON 和超过 64 KiB 的正文。任务写入始终要求有效 Bearer 认证，原有 DELETE 路由也要求版本及执行保护。

批量删除在 Job 准入锁内一次扫描完整索引，而非使用界面的十条回执预览。有关联非终态或存活 owner 时拒绝删除；无法确认归属的损坏记录也拒绝清理。锁覆盖检查与删除，防止新执行在检查期间进入。任务存储在跨进程锁内再次验证版本及 completed 状态。

批量文件操作不是跨文件事务，响应逐项报告更改与未更改原因。原生写入失败或超时可能已产生部分结果，只重新读取列表，不自动重放写入。确认及请求期间禁用重复操作；关闭窗口后旧读取回包失效。客户端保留 loopback 路径白名单、禁止代理/重定向、响应大小限制和认证头隔离。

`scripts/test/test-macos-app.sh` 继续覆盖其他原生组件与安装包结构。合成窗口不能替代安装后真实菜单、前台应用切换、多桌面与权限状态验收；安装包验证不会替换正在运行的应用。
