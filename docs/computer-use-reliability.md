# Computer Use：可靠执行、任务范围与条件验证

## 本轮目标

基于 `3c169a8` 的五项审查发现，修复停止丢失、清理错误被吞、显示目标错位、事件跟踪期间心跳误超时和预览故障不恢复。在此基础上增加 `desktop_task`、`desktop_wait`、任务内应用授权、单步执行、紧急停止和有界事件记录。

这不是无人值守桌面沙箱，也不声明与 Codex 的内部实现一致。原有默认后台、不激活应用、不自动降级全局输入、不绕过 macOS 权限的边界保持不变。

## 正式宿主调用协议

正式 Core 启用桌面能力后，同时要求本机监视器在线和独占任务。七个工具为 `desktop_status`、`desktop_task`、`desktop_permissions`、`desktop_launch`、`desktop_snapshot`、`desktop_act`、`desktop_wait`。状态查询和不带目标的窗口元数据发现不需要任务许可，但不能生成可输入的快照或干扰正在使用的快照。

```json
{"action":"begin","title":"在指定应用完成本次界面操作"}
```

传给 `desktop_task`，获得 64 位十六进制随机 `task_id`。此值是该任务的私有能力令牌；只在 begin 响应返回，不能从 `desktop_status`、本机面板、时间线或其他任务中取得。之后的启动、权限请求、目标观察、等待和输入都必须携带它。`task_reference` 是另一随机生成的公开短标识，用于本机显示，不能授权操作。

```json
{"task_id":"<本任务令牌>","app_name":"Safari"}
```

传给 `desktop_launch`，然后在本机浮窗批准该应用的后台访问。选择返回的 PID 和窗口，再观察、操作和验证：

```json
{"task_id":"<本任务令牌>","window_id":456,"pid":123,"accessibility":true}
```

```json
{"task_id":"<本任务令牌>","action":"click","snapshot_id":"<刚观察得到的ID>","element_id":"e4"}
```

```json
{"task_id":"<本任务令牌>","pid":123,"window_id":456,"condition":"element_enabled","element":{"role":"AXButton","title":"Continue"},"timeout_ms":8000}
```

最后一个调用交给 `desktop_wait`。条件达成后仍须重新获取快照，再执行下一次输入。任务完成且没有未结束的操作后调用：

```json
{"action":"end","task_id":"<本任务令牌>"}
```

同一 Core 只保留一个独占任务，不启动多个并发写桌面的任务。发起方遗失令牌或退出时，由本机用户停止操作，再通过菜单栏“结束并释放桌面任务”释放占用。空闲 60 秒只结束当前视频/操作会话，**不自动释放任务所有权或清除本机停止状态**。

### 能力所有权不是客户端身份认证

MCP HTTP 入口当前采用无状态传输，不能以模型填写的 client name 或 task title 推断认证身份。本轮采用不可猜测的随机任务能力，防止其他正常调用者无令牌覆盖目标/快照；没有增加跨账户、跨 OS 用户或跨进程持久化的身份授权系统。拥有相同 OS 用户权限的进程、可执行任意本机命令的工具以及主动分享令牌的客户端不在此隔离保证内。任务令牌不要写入文档、日志或复制给另一任务。

## 本机应用授权

第一次访问应用时，核心先等待面板中的“允许本次任务”或“拒绝”，再捕获窗口、读取控件或启动/控制应用。授权请求有随机 ID，旧卡片不能批准新目标。授权等待最多 30 秒；超时不发送输入或自动转换模式。

有 Bundle 信息时授权键为 **Bundle ID + 规范化的应用路径 + 后台/前台模式**。没有 Bundle 的测试或普通进程使用实际 PID + 模式；无法从当前应用元数据识别目标时拒绝操作。后台允许不等于前台允许，切换模式要再次批准。前台授权明确说明它可能影响整个桌面：原有前台截图和输入是全局模式，并不是窗口隔离模式。

授权和拒绝均仅在当前任务中有效，任务结束时清除。本轮不实现永久白名单；“拒绝”不会因重新调用同一工具而反复弹卡。系统辅助功能/屏幕录制权限与本次任务应用授权是两个独立层次，彼此不能替代。

AgentDock Core 自身、当前本机控制器 PID、AgentDock 应用标识及系统设置、登录/安全代理的已知标识禁止自动操作。不能把它当成穷尽所有敏感应用的沙箱名单；敏感业务操作仍需调用方遵守用户确认要求。

## 条件等待

`desktop_wait` 只读观察，不点击、不输入、不重放上次动作、不激活窗口、不读取 AXValue，不消耗已有模型快照。

| 条件 | 验证语义 |
| --- | --- |
| `window_exists` | 指定 PID 下精确且唯一的可见窗口满足选择器。 |
| `window_absent` | 已观察过的 window ID 不在当前完整可见窗口列表；不表示进程退出，也不表示保存成功。不能同时传 window_title，避免重命名误判消失。 |
| `window_stable` | 同一窗口身份、标题和几何在指定稳定时段保持一致；不表示内部动画/业务已经完成。 |
| `element_exists` / `element_absent` | 在指定窗口的完整有界 AX 树中验证精确选择器。存在要求唯一；不存在不能由截断或窗口丢失推断。 |
| `element_enabled` / `element_disabled` | 唯一匹配元素的 AXEnabled 属性存在且值已明确获知；属性缺失不是 disabled。 |

元素选择器可使用精确 `role`、`title`、`description`，至少指定一个。不接受从旧快照复制的 element ID 作为跨观察长期身份。窗口或控件歧义、AX 树截断、窗口列表截断、未知 enabled 状态会保留“不确定”，不会变成成功。

默认等待 10 秒，最大 30 秒；`timeout_ms:0` 只观察一次。轮询间隔默认 200 毫秒，范围 100–1000；稳定时段默认 300 毫秒，范围 100–5000。每次采样有原生有界调用，阻塞系统调用可能在等待期限之后才返回，但不会把过期样本判成达成。轮询间隔释放输入锁，暂停和停止仍可取消等待。

返回 `met` / `condition_verified` 表示仅指定谓词被观察证实；`application_verified` 仍为 false。`timed_out:true`、`met:false` 是未证实，不是再次点击/提交的指令。调用方取消与本机暂停停止按错误返回，不伪装成条件达成。`last_observation` 记录可见窗口、匹配数、完整性和原因，不包含 AX 路径或输入值。

## 人工接管、单步和诊断

暂停即交回人工操作：立即取消排队/正在执行的桌面动作，等待必要释放。只有本机恢复可生成新代次，旧快照失效。

“执行下一步”允许新的观察/等待，以及**最多一个会改变状态的桌面操作**。一次点击、输入、启动或权限请求结束后自动暂停；不会把旧快照和上一动作重放。多次观察不消耗这一步许可。

本机注册 `Control-Option-Command-F12` 作为紧急停止。它只注册该组合，不监听或记录其他按键，不占用普通 Esc。注册冲突/失败会在菜单提示，普通停止按钮仍可用。本轮组合固定，未提供快捷键自定义界面；部分键盘可能需要 Fn。它只停止当前 Core 的桌面控制，不停止模型推理、终端或其他工具。

核心保留最近 32 条内存事件，菜单显示最近 6 条。记录序号、动作类型、PID/window ID、耗时及 `dispatched`、`wait_met`、`wait_timeout`、`cancelled`、`failed_or_partial`、`cleanup_failed` 或 `finished_unverified`。不保存输入正文、具体按键、截图、AX 标签、任务令牌，也不提供录制回放。通用完成不代表业务结果已验证。

## 五项修复的核心约束

1. **停止与暂停意图保留到确认。** IPC 失败后，后续心跳携带同一会话的意图，核心先处理意图再续租；不能因恢复普通心跳而继续输入。仅这些控制意图幂等确认，业务输入绝不自动重放。
2. **清理失败单独锁存。** 鼠标抬起错误与取消错误合并保留，核心进入 `cleanup_failed`，界面保留检查提示、不允许普通恢复。用户明确检查并确认人工清理后仍停在 stopped，恢复是另一步。
3. **监视目标与实际动作一致。** 启动前置失败不能先污染显示目标；执行时从当前有效快照重建监视目标。等待应用授权后还要检查快照时效。
4. **事件跟踪模式仍能心跳。** Timer 注册公共模式，IPC 在线程执行，回包直接投递主 RunLoop 的 common/eventTracking/modalPanel 模式。不能只把 Timer 改 common，再依赖可能被嵌套菜单循环延迟的 MainActor Task。
5. **预览按错误类型恢复。** 瞬时错误对同一目标最多尝试 4 次，带有界退避；稳定输出后才重置预算。用户主动停止、拒绝授权、缺权限不会自动重启；收起再展开不能解除此锁存，只有显式本机“重新尝试预览”可以再次尝试。

## 验证与部署

正式回归包含 `fault_regression_test.go`、`task_scope_test.go`、`wait_test.go`、`reliability_invariants_test.go`，以及 Runtime 的输入/输出契约测试。Mac 打包门禁运行不采集屏幕的预览故障测试。显式 native 测试覆盖真实面板、应用授权、AX 条件等待、单步、取消释放、失联保护，并以专用 IPC 故障注入验证停止消息丢失和菜单跟踪。

必须同时更新 Core 与菜单栏应用、刷新 MCP 工具定义。旧客户端缺少任务令牌或旧面板不能展示授权卡片时，操作会被明确拒绝，不增加自动兼容绕过。真实验收状态与日志见 [macos-computer-use-verification.md](macos-computer-use-verification.md)。

仍未覆盖所有 macOS/Intel/多显示器/第三方应用组合。后台指针现有非公开 `CGEventSetWindowLocation` 依赖未被这轮改动移除，系统升级后仍需重新验证。没有跨进程持久化停止锁、永久应用策略或后台任务队列。
